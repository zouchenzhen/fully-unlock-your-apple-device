# 公共检查与恢复范围

先选模块，再做相应检查。不要因为一次任务提到 iPhone，就把所有检查、全量备份和系统修改都执行一遍。

## 设备和能力

确认目标功能、准确型号、系统版本及 build；耳机任务加固件，手表任务加 watchOS 和配对 iPhone。读取最低必要信息，不列出整台手机的 App、账号或位置历史。

`scripts/device_preflight.py` 是只读 USB 预检，可查看公开设备状态。它不自动发起配对、不改加密设置，也不输出设备唯一标识。缺少本地运行能力或手机未连接时，应说明缺少什么，让用户完成连接，不虚构检测结果。

设备状态、上游 API 和地区可用性可能变化。复现前核对当前官方功能说明与工具所支持的版本。不要将某次机型组合的成功推广到所有 iOS、固件或地区。

## 按操作选择备份

| 操作 | 开始前需要什么 | 不自动做什么 |
| --- | --- | --- |
| Siri 的 MobileGestalt 写入 | 当前设备的原始缓存、正式设备绑定导出、保存位置、恢复方法；检查已有整机备份日期和完成状态 | 重做全量备份、改备份密码、覆盖原始文件、升级系统 |
| USB 配件定位 | 记录真实定位，停止冲突的循环定位，明确发送时限和停止方法 | 写系统缓存、要求完整备份、修改账号地区 |
| Watch 高血压通知实验 | 官方适用条件、配对状态、原始位置与通知状态、用户接受未实测流程 | 代填年龄或诊断问答、删健康数据、假定同款已验证 |

原始文件放在用户指定的私有目录，备份应在写入前读回或校验。App 正式导出附带的设备证明依赖本机密钥；卸载 App 不会自动恢复系统，也可能丢失恢复环境。系统更新导致缓存布局不同，应停止导入旧缓存。

## 网络与账号

将手机访问 Apple／ChatGPT 的路径与电脑签名工具访问 Apple 开发者服务的路径分开检查。对具体失败接口测试直连及现有本机代理，不能只测代理端口是否在监听。

优先给需要代理的单个子进程传递代理，不改变其它服务的全局网络。保留 TLS 证书校验，不安装自定义 CA 来尝试旧版定位中间人方法。

签名账号可以不同于手机 iCloud。登录、密码、验证码和信任操作由用户本人完成。账号错误不是驱动错误；证书上限也不是撤销所有证书的理由。

## 结果记录

记录成功到哪一层：连接、签名权限、读取、写入、重启保留、菜单、资源、实际调用、恢复。收到订阅或 ACK 只说明协议阶段成立，不能替代地图或功能验证。

来源分成四类：

- **本机实测**：记录设备、日期、版本和实际观察。
- **用户或他人反馈**：保留反馈范围，不自动升级为本包支持。
- **源码推断**：解释为何选择步骤，但仍需设备验证。
- **第三方教程**：标明尚未实测，列出待确认条件。

只完成入口验证时不要写“永久解锁”。用户取消后先停止本次进程；真实定位恢复、功能保留和系统设置恢复分别记录。
